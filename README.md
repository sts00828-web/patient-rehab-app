# 患者リハビリチェックアプリ

患者が自宅で実施・痛み・メモを記録し、来院時に担当PTと振り返る端末内保存型PWAです。

## 手元で開く

このフォルダで次を実行します（Pythonを使用）。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザで http://127.0.0.1:8765/ を開いてください。ファイルの直接ダブルクリックではQRやPWA機能が正しく動作しない場合があります。

初回は「スタッフ：メニューを設定」または画面上部を2秒長押し。PIN未設定なら空欄で確認します。

1. 患者の呼び名・開始日を設定。
2. 疾患を選び、目的・難易度・検索で候補を絞ります。必要な種目にチェックし、個別指示7項目と曜日を確認。「イラスト・手順を確認」で患者表示も確認します。
3. 個別の注意点・動画URLを必要に応じて編集し、相談先・痛みを記録する場面・再開の個別指示を設定。共有前の確認画面で内容を確認します。
4. 患者の端末へアプリ追加用QRを案内し、アプリ内カメラで設定QRを読み込む。
5. 受信端末で患者の呼び名を設定。日々の記録は来院時のレポートで確認。

## データの扱い

`localStorage.rehab_v2` に設定・記録・カスタムテンプレート・退避記録をまとめて保存します。一度の書き込みで更新し、保存失敗時は直前の状態へ戻します。

旧版の3キーは初回移行時に `rehab_legacy_backup` にそのまま退避し、既存キーも削除しません。当時の処方を復元できない旧記録は、チェック・痛み・メモを保持して「旧記録」と表示します。当時の達成率を推定して表示することはありません。

患者側の「自分の記録をバックアップ」は現在の患者だけを出力します。スタッフの「端末全体をバックアップ」は退避記録・テンプレートも含みます。PINはバックアップやQRで転送せず、端末固有の簡易ロックとして扱います。

PINは認証基盤や暗号化ではありません。QRには運動内容と個別の注意文が含まれます。個別の注意文に氏名などを書かず、本人に直接渡してください。既存の旧形式URLの受信は維持していますが、新しく生成するURLに患者プロフィールは含みません。

### TASK-021 / 未公開 SW v53：アプリ内の設定QRカメラ

固定240pxの読取枠を外し、白い余白を含む全フレームを解析します。背面カメラ・1920×1080を `ideal` で要求し、制約非対応（OverconstrainedError / ConstraintNotSatisfiedError / TypeError）時だけ、解像度指定なしで1回再試行します。権限拒否や機器使用中では再要求しません。解析はQR限定・毎秒5回を目安とし、開始待ちキャンセル・二重起動防止・終了後1回だけ取込の制御を維持しています。

同梱 html5-qrcode 2.3.8 の `setupUi` / `foreverScan` は表示上のCSS幅まで解析canvasを縮小していました。高解像度要求だけでは細かいQRの画素が失われるため、明示的な `useNativeResolution` オプションを局所追加しました。有効時はカメラ画素を保持し、処理量を抑えるため長辺1920pxを上限にします。既定動作は従来どおりです。変更位置・更新時の注意は `vendor/README.md` を参照してください。
